# Docs section map: every section of every tracked documentation page, and
# whether a test reads it.
#
# A page is listed here as [path]. Under it comes every `##` and `###` heading
# of that page, written exactly as the page writes it, each followed by one
# indented line:
#
#   joined: tests/<file>   that test reads what this section states
#   prose: <reason>        no test reads it, and the reason says why that is
#                          fine or names what is left unchecked
#
# tests/check-invariants.sh ("Docs section map") fails when a tracked page has
# a heading with no row here, when a row names a heading the page no longer
# has, or when a `joined:` test does not exist or names the page only in a
# comment. It does not prove any sentence true. What it changes is that a
# section of claims about the machine that nothing checks shows up as a
# `prose: unchecked:` line in the diff that adds it, instead of being the
# silent default.
#
# `prose: unchecked:` marks a section that states facts about the machine (a
# workflow, the Containerfile, .claude/settings.json, the Bash guard hook, the
# ruleset, renovate.json) that no test reads. Each one is a candidate for a
# join test; turning it into `joined:` is the fix. `prose: narrative:` marks a
# section that states no such fact.
#
# A `joined:` row means the test reads something written in that section,
# either by extracting the section or by a page-wide check that covers a claim
# in it (the fenced commands of docs/installation.md, the gh commands of
# docs/ai-ops-runbook.md). A check that only looks for the heading is not a
# join, and such a section is classified `prose:` with the reason saying so.
#
# Tracked pages: every tracked Markdown file at the repository root, in docs/
# (not its dated subdirectories) and in docs/security/, plus
# .github/copilot-instructions.md. A new page in one of those places has to be
# added here in the change that adds it.
